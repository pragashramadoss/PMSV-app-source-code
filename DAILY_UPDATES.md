## App notifications (replaces email and WhatsApp)

Never print, export, or include those records in source/news JSON. Public config returns only the public key. Keep these tables during daily updates.

Before publishing a daily edition, generate a cryptographically random publisher secret (at least 32 bytes) in memory and use Sites update_environment_variables to set PMSV_DISPATCH_SECRET as is_secret=true. Retain it only in that execution context. Deploy the edition to apply it, then authenticate the dispatch using that same secret. This rotates the existing publisher credential without exposing it in source, prompts or logs. Never dispatch if publication failed. If secure configuration is blocked, publish news with the existing environment unchanged and report the delivery limitation.

After each successful public deployment, POST to `https://pmsv-food-safety-updates.pragash-ramadoss.chatgpt.site/api/push/dispatch` with no body and an Authorization: Bearer header containing the PMSV_DISPATCH_SECRET from a secure publisher runtime. Never call it without authorization, put this secret in a URL, print it, or put it in source. If the scheduled environment cannot access the secret securely, report notification delivery as unavailable and continue publishing news; do not weaken this protection. This is explicitly requested notification delivery, not a deployment verification fetch. The endpoint accepts no user-supplied recipients/content and sends only unseen published news to opted-in devices. Repeat bounded batches while `remaining > 0` (up to 50 batches per run; report backlog if any). Inspect `failed`; transient failures are deferred for one hour and eligible at the next dispatch. Report delivery failures; do not describe provider acceptance as confirmed device receipt. Do not dispatch on a failed deployment.

The delivery cursor is based on `firstSeen`. Preserve existing values and timestamp genuinely new records correctly. With no new items, dispatch sends nothing; new subscribers start after the existing archive. Do not change firstSeen simply to re-send stories. No email service, phone number, sender domain purchase or paid notification provider is required for this implementation. Real delivery still depends on browser push services, connectivity and user permissions.
